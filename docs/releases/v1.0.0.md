# AgriCore v1.0.0 release notes

## Overview

[v1.0.0](https://github.com/JasonTM17/AgriCore_SpringBoot_Microservices/releases/tag/v1.0.0)
is the first source release of AgriCore. It packages the completed agricultural
operations platform: 13 Spring applications, the React console, versioned
OpenAPI/AsyncAPI contracts, local Compose stacks, an application Helm chart,
security and supply-chain workflows, and repository-owned demo evidence.

See the [changelog](../../CHANGELOG.md), [project overview](../project-overview-pdr.md),
and [system architecture](../architecture/SYSTEM_ARCHITECTURE.md) for feature
scope and design boundaries.

## Compatibility and operator boundary

- The source tag is the source-release identity. It is **not** a Docker image
  tag and does not identify a mutable runtime artifact.
- The publishing workflow promotes immutable seven-character and full-SHA image
  tags to Docker Hub and GHCR, never `latest`. Resolve the release target to its
  recorded full-SHA image tag, then deploy the registry digest.
- The Helm chart expects digest-pinned application images by default. It does
  not provision PostgreSQL, Redis, Kafka, MQTT, object storage, SMTP, ingress,
  TLS, backups, Kafka ACLs, or observability backends.
- Package publication and a signed digest do not prove a production deployment.
  Operators own environment secrets, infrastructure, access policy, retention,
  migration planning, rollout approval, and incident handling.

## Verification procedure

1. Confirm the GitHub Release target and its linked default-branch CI and Docker
   Publish evidence.
2. Resolve each required image from the release target's full-SHA tag to an
   immutable digest; compare Docker Hub and GHCR where both registries are used.
3. Verify the selected digest and signature before deployment:

   ```bash
   docker buildx imagetools inspect IMAGE@sha256:DIGEST
   cosign verify IMAGE@sha256:DIGEST \
     --certificate-identity-regexp 'github.com/.+/.github/workflows/docker-publish.yml@refs/heads/(main|master)' \
     --certificate-oidc-issuer https://token.actions.githubusercontent.com
   ```

4. Use an environment-owned Helm values file with each application image pinned
   as `repository@sha256:<digest>`, validate/render it, and follow the
   [deployment guide](../deployment-guide.md#helm-release).
5. Treat migrations, published events, and external dependencies as an operator
   rollout decision; Helm rollback does not undo those effects.
